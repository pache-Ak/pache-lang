对象（变量）间的资源所有有三种关系（TODO 重新考虑用词*关系*）

1. 移动
   移动后原有对象不在持有资源，资源由新的对象持有。
2. 拷贝
   拷贝后两对象都持有资源，两份资源相同但不是同一个。
3. 引用
   两对象共同持有同一个资源。
   引用对象（变量）不一定需要有自己独立的地址，

```cpp
  let i32 a = 1;
  let i32 &b = a;
  std::cout << &a << " " << &b << "\n";
```

### 引用的生命周期不能长于被引用对象（变量）
引用和指针指向的对象的生命周期不能长于被引用对象（变量），
否则会发生悬垂引用，进一步导致一些错误。

#### 可能出现问题的场景
局部变量的引用返回：当函数返回一个局部变量的引用时，该局部变量的生命周期随函数结束而结束，但引用仍然存在。

```cpp
int& func() {
    int a = 5;
    return a; // 返回局部变量的引用
}
// func() 的返回值是一个悬垂引用
```
对象的作用域结束：当对象的生命周期结束后，任何指向该对象的引用都会变成悬垂引用。

```cpp
int* ptr;
{
    int x = 10;
    ptr = &x;
} // x 的作用域在这里结束
// 现在 ptr 成了一个悬垂指针，因为它指向的内存已经不再有效
```
动态分配内存的错误管理：如果动态分配的内存被释放或删除，任何指向该内存的引用都会变悬垂。

```cpp
int* ptr = new int(10);
delete ptr;
// 此时 ptr 指向的内存已经被释放，ptr 成为悬垂指针
```
临时对象的引用保存：如果对临时对象进行引用或保存，就会产生悬垂引用。这是因为临时对象的生命周期不会延长到引用或保存它们之后。当临时对象被销毁后，引用就变成了悬垂引用。

```cpp
int& my_reference = 10 + 20; // 创建一个临时对象，将其引用保存到my_reference中
```
lambda表达式中的悬垂引用：在使用lambda表达式时，如果捕获了局部变量的引用，而这些局部变量的生命周期结束后，lambda表达式仍然存在，就会产生悬垂引用。

```cpp
int* createInt() {
    int x = 10;
    auto lambda = [&]() {
        return &x;
    };
    return lambda();  // 返回一个指向已销毁变量的指针
}
```
迭代器和容器操作导致的悬垂引用：在对容器进行操作时，如果改变了容器的内容，可能会导致迭代器、指针或引用指向的元素被删除或移动，从而产生悬垂引用。

- lvalue（左值）

- gvalue（泛左值）

### 纯右值作为函数参数
纯右值作为临时产生的临时量，会存在于cpu寄存器或内存中，
不需要，不存在一个固定的内存地址。
1. 按值传递
临时量会被拷贝到栈帧对应参数的地址中。
2. 按引用传递
引用传递的是对象的地址，临时量没有地址，此时需要将临时量实质化。
在cpp中，无论左值引用还是右值引用都可能会以指针形式传递，都需要临时量实质化。
暂不考虑提供语法糖来隐式的作临时量实质化。


## 引用能否绑定亡值？

亡值具有地址可以被绑定，但是亡值不具有合法状态的对象，此时引用所指代的对象需要按照未初始化对象来处理。

若允许引用绑定亡值，则必须限制或条件限制引用的功能。

考虑是否特化一种亡值引用。

创建新的对象，而不是重新初始化亡值，由编译器考虑内存的复用，进一步可以考虑禁止访问亡值，禁止将亡值绑定到引用。

参考rust的规则，目前设计采用禁止访问、使用、绑定亡值。
